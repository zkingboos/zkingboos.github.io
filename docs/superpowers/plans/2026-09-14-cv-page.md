# CV Page (Currículo) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Criar uma página de currículo (`/cv`) em React com layout estilo LinkedIn (fundo claro), reutilizando os dados já estruturados do site, com botão "Baixar PDF".

**Architecture:** Nova rota `/cv` no react-router que renderiza um componente `CvPage`. O componente lê os dados de `src/config/site.ts` (personalInfo, experienceContent, projectsContent, skillsContent, openSourceContent) e os apresenta num layout LinkedIn claro. O botão "Baixar PDF" usa **`react-to-print`** (o PDF é gerado a partir do próprio componente React). Os dados são **fonte única** em `config/site.ts` — site e CV compartilham o mesmo arquivo, sem duplicação.

**Tech Stack:** React 18, TypeScript, Tailwind CSS, react-router-dom, react-i18next, `react-to-print`.

**Spec:** (não há spec formal; este plano é auto-contido e segue o alinhamento: estilo LinkedIn claro, download via componente React/print.)

## Global Constraints

- Fundo **claro** (branco/`#ffffff`), tipografia sóbria tipo LinkedIn (Inter, já disponível).
- Layout LinkedIn: caixas com borda sutil + `border-radius`, hairlines internos, título em negrito.
- Seguir o idioma ativo (pt/en) via `react-i18next` — os dados de `config/site.ts` já são `LocalizedText`.
- Reutilizar os dados de `src/config/site.ts`; NÃO duplicar dados duros.
- **REGRA DE DADOS COMPARTILHADOS (fonte única):** `src/config/site.ts` é a única fonte de verdade para experiência, projetos, skills, open source, idiomas e contato. Tanto a página principal (`Index`) quanto a página CV (`/cv`) leem deste mesmo arquivo. Qualquer mudança de dado é feita APENAS em `config/site.ts`; o CV reflete automaticamente, pois não tem dados próprios. NUNCA criar um `config/cv.ts` separado nem dados duros no `CvPage.tsx`.
- Um teste de consistência (Task 0) garante que os campos que o CV consome existem em `config/site.ts` e falha o build se alguém remover/quebrar um campo obrigatório.
- Botão "Baixar PDF" usa `react-to-print`; uma dependência nova (`react-to-print`).
- Fidelidade aos dados: não inventar informação além do que está em `config/site.ts`.

- [ ] **Step 3: Envelopar o conteúdo CV com `forwardRef`**

Em `CvPage.tsx`, transformar o componente num `forwardRef` que recebe `ref` e o aplica ao wrapper do conteúdo:

```tsx
import { useRef } from "react";
import React from "react";
import { useReactToPrint } from "react-to-print";

const CvContent = React.forwardRef<HTMLDivElement>((_props, ref) => {
  // ... TODO o conteúdo (header, sections) ...
  return <div ref={ref} className="max-w-3xl mx-auto px-6 py-8 bg-white text-zinc-900">...</div>;
});

export default function CvPage() {
  const printRef = useRef<HTMLDivElement>(null);
  const handlePrint = useReactToPrint({
    contentRef: printRef,
    documentTitle: "curriculo-jose-gabriel",
  });

  return (
    <div className="min-h-screen bg-white text-zinc-900" data-lenis-prevent>
      <button
        onClick={() => handlePrint()}
        className="print:hidden fixed top-4 right-4 z-50 px-4 py-2 rounded-lg bg-[#09a6d6] hover:bg-[#0ca9cf] text-white font-mono text-sm shadow-lg"
      >
        Baixar PDF
      </button>
      <CvContent ref={printRef} />
    </div>
  );
}
```
